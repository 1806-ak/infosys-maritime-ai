# Infosys Portal Authentication System

A Python-based web application that provides user registration, login, session management, and password recovery through a clean and interactive interface built with Streamlit.

## 📌 Project Overview

The Infosys Portal Authentication System is designed to demonstrate the core concepts of user authentication and account management. It allows users to create accounts, sign in using their credentials, access a dashboard, and recover their passwords through a security question.

The application uses SQLite for database management and bcrypt for password hashing. Ngrok can be used to expose the locally running application through a public URL for demonstration purposes.

## ✨ Features

- **User Registration:** Create a new account with a username, email, and password.
- **Secure Login:** Verify user credentials using stored password hashes.
- **Password Hashing:** Hash passwords using bcrypt before storing them in the database.
- **Session Management:** Maintain authentication state during application use.
- **Dashboard Access:** Navigate to the dashboard after successful authentication.
- **Password Recovery:** Reset a password after verifying the registered security answer.
- **Input Validation:** Check required fields, password length, and password confirmation.
- **Interactive Interface:** Use a simple, responsive interface built with Streamlit.
- **Public Demo Access:** Use ngrok to share the running application through a public URL.

## 🔐 Authentication Workflow

### 1. User Registration
- Enter a username, email address, and password.
- Confirm the password and select a security question.
- Validate the submitted information.
- Hash the password and security answer before storing them in SQLite.
- Create the account and proceed to the dashboard after successful registration.

### 2. User Login
- Enter the registered email address and password.
- Retrieve the stored password hash from the database.
- Verify the entered password using bcrypt.
- Grant access to the dashboard if verification succeeds; otherwise, display an error message.

### 3. Password Recovery
- Enter the registered email address.
- Select the security-question verification option.
- Submit the answer and choose a new password.
- Verify the answer against its stored hash.
- Update the password hash after successful verification.

## ⚙️ Installation and Setup

### Prerequisites
- Python 3.9 or later
- pip package manager

### Step 1: Clone the Repository

```bash
git clone <YOUR_REPOSITORY_URL>
cd Infosys-Portal
```

Replace `<YOUR_REPOSITORY_URL>` with your actual repository URL.

### Step 2: Install Dependencies

```bash
pip install streamlit bcrypt PyJWT
```

Install `pyngrok` as well if your application uses it:

```bash
pip install pyngrok
```

### Step 3: Run the Application

```bash
streamlit run app.py
```

Open the local URL displayed in the terminal, usually:

```text
http://localhost:8501
```

### Step 4: Optional Public Access with Ngrok

Configure ngrok according to your environment, then expose port 8501:

```bash
ngrok http 8501
```

Use the public URL generated by ngrok to access the running application.

## 🗄️ Database Design

The application uses an SQLite database with a `users` table.

The table stores fields corresponding to:

- User ID
- Username
- Email address
- Password hash
- Security question
- Security-answer hash

The database schema and column names should match the SQL statements in the application code.

## 🛡️ Security Considerations

- Passwords are stored as bcrypt hashes rather than plain text.
- Security answers are hashed before storage.
- Parameterized SQL queries are used for database operations.
- Authentication state should be checked before displaying protected pages.
- Secrets, API tokens, and credentials should be stored in environment variables or a secrets manager.
- Production deployments should use HTTPS and secure session/token handling.
- Password reset attempts should be protected against abuse.
- The SQLite database should be backed up if account data must persist across runtime restarts.

**Important:** A public ngrok URL is intended for demonstration and does not, by itself, make the application production-ready. Review session security, token expiration and validation, account protection, and deployment settings before using real user information.

## 🚧 Current Limitations

- SQLite data may not persist if the database is stored in a temporary environment that is reset.
- Public ngrok URLs may change between sessions.
- OTP-based recovery requires a separately implemented and configured OTP workflow.
- Production use requires additional security testing and deployment hardening.
